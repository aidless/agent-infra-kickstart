# 变更证据闸（pre-commit 第 4 闸）落地记录

- 时间：2026-11-13
- 起因：LobeHub 四层对照（`notes/2026-11-13-lobehub-四层对照.md`）里 L2「验收证据落盘=缺」——本仓没有任何位置强制「这次改动带了什么证据」。
- 落点：`scripts/hooks/pre-commit.d/40-change-evidence.sh`（新建，755）

## 1. 实测表

| 项 | 命令/位置 | 结果 |
|---|---|---|
| `-m` 时 `COMMIT_EDITMSG` 是否存在 | `/tmp/cit` 临时仓，pre-commit 里判 `-f .git/COMMIT_EDITMSG` | **root commit: NO**；同仓第二次 commit: YES |
| `-F <file>` 时是否存在 | `/tmp/cit2`，`git commit --allow-empty -F /tmp/msg.txt` | **NO** |
| 判例闸 | `~/.local/bin/pw scripts/hooks/pre-commit.d/40-change-evidence.sh` | `ALLOW — no open precedent` |
| 自检 | `./scripts/hooks/pre-commit.d/40-change-evidence.sh --selftest` | **13/13 PASS**，`EXIT=0` |
| 聚合器纳入 | `/tmp/gates-integ`（git init + 4 个闸 + `run-gates.sh --status-json`） | 名单含 `40-change-evidence.sh`；无凭据 exit=1、补 notes 后 exit=0 |
| 真实仓空 staged | 工作区直接跑闸 | `EXIT=0`（不误拦既存状态） |

结论：**commit message 不能作凭据的唯一通道**——三条 commit 路径里有两条读不到 `COMMIT_EDITMSG`。这是把凭据主通道放到「同 commit 落盘的文件」而非 message 的硬理由，不是偏好。

## 2. 判据

三条通道任一满足即放行（脚本头注同文）：

- **A** 同一次 commit 里 staged 了 `notes/*.md`，且其 **staged 内容**（`git show :path`，非工作区内容）含 `## 验收`（或 `## Verification`）标题下至少一行非空正文；
- **B** 本次**新增**（`diff-filter=A`）的 `scripts/` 或 `.agent-memory/precedent/` 文件自带 `# 验收: <非空>` 标记行；
- **C** `.git/COMMIT_EDITMSG` 可读时含同一 `## 验收` 段。

风险面只覆盖 `^(scripts/|\.agent-memory/precedent/)`；其余路径（`notes/`、文档、数据）放行。退出码 `0`=放行 / `1`=阻断 / `3`=闸没执行（≠通过）/ selftest 失败 `5`——`3` 与 `1` 分开是为对齐 `run-gates.sh` 的「3 优先于 2 优先于 1」保留规则。

逃生：`CHANGE_EVIDENCE_BYPASS=1 CHANGE_EVIDENCE_REASON="<非空>"`，理由为空**仍拦**（对齐条 20「override 必须带非空 reason」），放行时追加 `.agent-memory/logs/change-evidence-bypass.jsonl` 并打 WARN。

## 3. 自检覆盖（条 8 + 条 21 + 条 37）

RED 5 条（注入违规必须 `rc=1`）：改已有脚本零凭据 / 验收段空正文 / 内容落在下一个 `##` 之下 / 自声明标记空值 / 逃生无理由。
GREEN 4 条（必须 `rc=0`）：notes 带验收段 / 新增脚本自声明 / 有据逃生 + **逃生留痕文件确已写出**。
假阳守卫 4 条（本不该拦的样本原样再跑）：只改 notes / 空 staged / 非风险路径 / 仅 notes 带验收段。

其中两条是**故意收紧**的：「验收段空正文」拦的是「写个 `## 验收` 标题就算交差」；「内容落在下一个 `##` 之下」拦的是——`awk` 状态机若不显式在下一个二级标题处 `insec=0`，后面任何正文都会被算成验收证据（这是本闸最可能的假阴，已配 RED3）。

## 4. 我自己写错的两条测试（不是判据的错）

- `RED1` 首跑 `want=1 got=0`：`sh "$GATE"` 外**没套 `cd "$BASE/r1"`**，闸在真实工作区跑（那里无 staged）→ 判据正确放行，测试自身失效。
- `RED3` 首跑 `want=1 got=0`：用例只 stage 了 notes，**没改脚本**，风险面为空 → 放行合理。补 stage 一个 `scripts/legacy.sh` 改动后转红。

两条都是「用例没造出被判对象」，不是放宽判据。修正后 13/13 PASS，判据一行未改。

## 5. 边界（这条闸管不到什么）

- **管不到「证据是真的」**：它只判「有没有一段非空的验收文字 / 有没有一行可执行命令」，不判那条命令真跑过。要判真跑过，得挂 `eval_acceptance_gate.py` 的 change 级版本（成本更高，见四层对照 ③）。
- **管不到语义**：`## 验收` 下面写「已修复」也能过。这是刻意取舍——本地 hook 看不到上游需求，只能保证「提交者被迫写下一句可反驳的话」，把责任从闸转给审阅者与判例闸（`pw` 查的是另一条轴：踩过的坑又踩了吗）。
- **B 通道只认新增文件**：583 个既有脚本不会因为被改动而强制补标记（会直接锁死日常改动）；它们要过闸只能走 A/C。

聚合器纳入验证（`/tmp/gates-integ`，4 个闸共存）：

```
--- case A: 改脚本无凭据
  40-change-evidence.sh 1        # 聚合器保留最严重码 3（来自另三闸缺输入）
--- case B: 补 notes 验收段
  40-change-evidence.sh 0
```

真实仓空 staged：`EXIT=0`。判例闸：`pw: ALLOW — no open precedent`。

读的是 **staged 版**而非工作区版（`/tmp/ev-var` 三连测）：

```
工作区有验收段但 notes 未 stage  => rc=1 [期望 1]
notes 已 stage                  => rc=0 [期望 0]
staged 版又把验收段删了          => rc=1 [期望 1]
```

这条很关键：否则「写完笔记忘了 `git add`」会被误放行，而 `git show :path` 拿到的是提交后真正落盘的那一版。
耗时 0.01–0.03 s（3 次实测），对提交无感。
